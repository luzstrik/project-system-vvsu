## Блок 1: Спортивные сооружения и инфраструктура

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|
| ФТ-ОБЪ-01 | Система должна вести учёт спортивных сооружений с базовыми атрибутами | Название, адрес, тип, площадь, год ввода в эксплуатацию, статус эксплуатации |
| ФТ-ОБЪ-02 | Система должна поддерживать специфические атрибуты в зависимости от типа сооружения | Стадион → вместимость; Корт → тип покрытия; Манеж → наличие трибун и т.д. |
| ФТ-ОБЪ-03 | Система должна фиксировать историю технических осмотров, ремонтов и простоев объектов | Дата начала/окончания ремонта, причина, ответственный подрядчик, статус готовности |
| ФТ-ОБЪ-04 | Система должна позволять фильтровать объекты по типу, характеристикам и статусу доступности | «Покажи все крытые арены вместимостью >5000, свободные в марте» |
| ФТ-ОБЪ-05 | Система должна вести реестр закреплённых организаций за каждым объектом | Муниципальная собственность, частная аренда, ведомственная принадлежность |

## Блок 2: Спортсмены и клубы

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|
| ФТ-СПР-01 | Система должна вести единый реестр спортсменов с персональными и спортивными данными | ФИО, дата рождения, контакты, текущий разряд, дата присвоения, фото |
| ФТ-СПР-02 | Система должна закреплять каждого спортсмена ровно за одним спортивным клубом | Нельзя числиться в двух клубах одновременно; при переводе сохраняется история |
| ФТ-СПР-03 | Система должна поддерживать принадлежность одного спортсмена к нескольким видам спорта | Баскетбол + лёгкая атлетика одновременно; связь «спортсмен ↔ виды спорта» многие-ко-многим |
| ФТ-СПР-04 | Система должна хранить историю изменения спортивных разрядов и званий | Дата, приказ, основание, скан-копия документа; возможность просмотра динамики |
| ФТ-СПР-05 | Система должна позволять формировать выборки спортсменов по клубу, виду спорта, разряду или возрасту | «Все КМС по плаванию из клуба «Дельфин» до 20 лет» |

## Блок 3: Тренеры и персонал

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|
| ФТ-ТРН-01 | Система должна вести учёт тренеров с указанием квалификации и специализации | ФИО, категория, стаж, вид спорта, контактные данные, место работы |
| ФТ-ТРН-02 | Система должна поддерживать связь «один спортсмен — несколько тренеров» в рамках одного вида спорта | Основной тренер + тренер по ОФП/технике; учёт ролей в тренировочном процессе |
| ФТ-ТРН-03 | Система должна фиксировать закрепление тренеров за группами/секциями и вести расписание | Нагрузка в часах, количество подопечных, пересечения в расписании |
| ФТ-ТРН-04 | Система должна позволять формировать списки тренеров по виду спорта или организации | «Все тренеры высшей категории по гимнастике в СШОР №3» |
| ФТ-ТРН-05 | Система должна отображать историю тренировочной работы тренера со спортсменами | Периоды работы, достигнутые разряды подопечными, участие в сборах |

## Блок 4: Соревнования и мероприятия

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|
| ФТ-СОР-01 | Система должна позволять создавать карточки соревнований с полным набором параметров | Название, даты, вид спорта, место, организатор, регламент, призовой фонд |
| ФТ-СОР-02 | Система должна привязывать каждое соревнование к одному виду спорта и одному сооружению | Нельзя провести многоборье на двух площадках одновременно в рамках одного мероприятия |
| ФТ-СОР-03 | Система должна учитывать организаторов с возможностью проведения множества мероприятий одним лицом | Юрлицо или физлицо; история проведённых событий, рейтинги, контакты |
| ФТ-СОР-04 | Система должна проверять расписание на конфликты по датам и доступности объектов | Предупреждение при наложении бронирований или занятости персонала |
| ФТ-СОР-05 | Система должна фиксировать изменения статуса мероприятия (перенос, отмена) с указанием причин | Погода, болезнь, техническая неисправность; автоматическое оповещение участников |

## Блок 5: Участие, результаты и награждение

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|
| ФТ-УЧА-01 | Система должна регистрировать заявки на участие от клубов/тренеров с проверкой допуска | Автоматическая сверка с реестром разрядов, возрастных категорий и меддопусков |
| ФТ-УЧА-02 | Система должна фиксировать результаты выступлений и занятые места в электронных протоколах | Время, очки, баллы, дисквалификации; поддержка разных систем подсчёта по видам спорта |
| ФТ-УЧА-03 | Система должна автоматически формировать списки призеров на основе утверждённых результатов | 1–3 места, дополнительные номинации; привязка к наградам |
| ФТ-УЧА-04 | Система должна вести учёт выданных наград с привязкой к спортсмену, соревнованию и дате | Медали, грамоты, денежные призы, спортивные разряды по итогам |
| ФТ-УЧА-05 | Система должна хранить полную историю выступлений спортсмена во всех соревнованиях | Возможность построить карьерную статистику, динамику результатов, рейтинг |

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|

| ФТ-МЕД-05 | Система должна отправлять автоматические уведомления тренерам об истечении срока справок | За 30/15/7 дней до окончания; снижение рисков недопуска в день старта |

## Блок 8: Безопасность и администрирование

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|
| ФТ-БЕЗ-01 | Система должна требовать обязательную авторизацию с разграничением прав по ролям | Администратор, организатор, тренер, врач, спортсмен/зритель (только чтение) |
| ФТ-БЕЗ-02 | Система должна вести журнал аудита изменений критичных данных | Кто, когда, какие поля изменил; возможность отката и расследования инцидентов |
| ФТ-БЕЗ-03 | Система должна обеспечивать резервное копирование и защиту ПДн в соответствии с 152-ФЗ | Шифрование чувствительных полей, регламент бэкапов, политика хранения |
| ФТ-БЕЗ-04 | Система должна позволять настраивать справочники без изменения кода | Виды спорта, типы сооружений, разряды, награды, причины отмен мероприятий |
| ФТ-БЕЗ-05 | Система должна предоставлять API для интеграции с внешними сервисами | Госреестры спорта, платёжные шлюзы, SMS/e-mail рассылки, метеослужба |
