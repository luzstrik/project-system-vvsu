# Лабораторная работа №3
## Бизнес-процессы предметной области (AS-IS)
### Информационная система «SportCity»

**Вариант 10. Проектирование информационной системы спортивных организаций города**

---

## Задание №1. Описание процессов в состоянии AS-IS

### 🔹 Основной процесс: `Организация и проведение городского соревнования`

| Параметр | Описание |
|----------|----------|
| **Цель процесса** | Успешно спланировать, провести и задокументировать спортивное соревнование на территории города. |
| **Инициатор** | Организатор соревнований / Спорткомитет города. |
| **Входные данные** | Заявка на проведение, утвержденное положение, график занятости объектов, списки допущенных спортсменов, медицинские справки, протоколы судей. |
| **Выходные данные** | Итоговые протоколы, списки призеров, данные для награждения, отчет о проведении, обновленная статистика по разрядам. |
| **Участники** | Организатор, судейская коллегия, спортсмены, тренеры, администрация сооружения, медицинская служба, спорткомитет. |
| **Ожидаемый результат** | Соревнование проведено в срок, результаты зафиксированы, отчетные документы переданы в спорткомитет и федерации. |

---

### 🔹 Вспомогательный процесс 1: `Ведение реестра спортсменов и клубов`

| Параметр | Описание |
|----------|----------|
| **Цель процесса** | Поддержание актуальных данных о спортсменах, их разрядах, принадлежности к клубам и медицинских допусках. |
| **Инициатор** | Тренер / представитель спортивного клуба / кадровая служба. |
| **Входные данные** | Анкеты спортсменов, копии медицинских заключений, приказы о зачислении, документы о присвоении разрядов. |
| **Выходные данные** | Обновленный реестр спортсменов, карточки клубов, списки допущенных/недопущенных к соревнованиям. |
| **Участники** | Тренеры, администраторы клубов, медслужба, ответственный за ведение баз (Excel/бумажные журналы). |
| **Ожидаемый результат** | Централизованный (но разрозненный в текущем состоянии) учет, позволяющий быстро формировать заявки на старты. |

---

### 🔹 Вспомогательный процесс 2: `Подготовка и учет спортивных сооружений`

| Параметр | Описание |
|----------|----------|
| **Цель процесса** | Обеспечить техническую готовность и бронирование спортивного объекта под мероприятие. |
| **Инициатор** | Ответственный за объект / техническая служба. |
| **Входные данные** | График аренды, заявки организаторов, акты технического осмотра, данные о ремонтах/покрытии. |
| **Выходные данные** | Подтверждение готовности, журнал бронирований, акты ввода/вывода объекта из эксплуатации. |
| **Участники** | Администрация объекта, техническая служба, организаторы, бухгалтерия (учет аренды). |
| **Ожидаемый результат** | Объект подготовлен, забронирован, соответствует требованиям безопасности и вида спорта. |

## Задание №3. Анализ проблем основного процесса (AS-IS)

| Возможная проблема | Причина | Последствие |
|-------------------|---------|-------------|
| **Дублирование ввода данных спортсменов** | Учет ведется разрозненно: клубы хранят данные локально, спорткомитет требует бумажные заявки, судьи заполняют свои бланки | Расхождения в ФИО, разрядах, клубах; ошибки в протоколах; потеря времени на ручную сверку |
| **Задержки при согласовании даты и места** | Ручной запрос в администрацию сооружения, отсутствие единого цифрового календаря бронирований | Срыв сроков подготовки, конфликт расписаний, простой объекта или экстренный перенос соревнования |
| **Ручная обработка медицинских допусков** | Справки передаются на бумаге, нет автоматической проверки сроков годности и привязки к спортсмену | Допуск спортсменов с просроченными справками, риск травм, юридическая ответственность организаторов |
| **Узкое место: ручное формирование протоколов** | Судьи заполняют бумажные бланки, затем оператор вручную переносит данные в Excel | Ошибки при транскрибации, задержка публикации результатов, жалобы спортсменов и тренеров |
| **Избыточность ввода контактных данных** | Каждый участник/тренер заново указывает телефон/email для каждой заявки | Усталость пользователей, ошибки в SMS/e-mail оповещениях, низкая явка на старт |
| **Риски утери данных о результатах** | Протоколы хранятся в бумажном виде или на локальных ПК без централизованного резервного копирования | Невозможность восстановления статистики, проблемы с присвоением разрядов, споры о призовых местах |
| **Отсутствие автоматического контроля разрядов** | Проверка соответствия разряда спортсмена требованиям соревнования выполняется вручную | Допуск спортсменов с неподходящим разрядом, аннулирование результатов, репутационные риски |
| **Задержки в передаче отчетов в Спорткомитет** | Отчеты формируются постфактум в виде документов, требующих ручной подготовки | Несвоевременное обновление реестров, проблемы с финансированием и планированием |
